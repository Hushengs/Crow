01 · 定位

为什么做 Crow

Crow 不是通用 CMS。它服务的是内容注入与播控运营：版权方把节目交给平台，平台再按服务商路由分发。后台要同时管「片库从哪来、发给谁、谁能改」。

内容

媒资编目

分类、影片、剧集、媒体文件、海报。电影 / 剧集 / 综艺共用一套节目树，而不是散落的文件列表。

分发

CP / SP 路由

内容提供商（CP）注入，内容服务商（SP）拉流。编码对应协议侧 CPID / SPID，多对多绑定决定注入路径。

治理

账号与审计

管理员、角色、权限、操作日志、系统日志。JWT 保护管理 API，变更可追溯。

02 · 范围

做什么，先不做什么

本期范围

后台登录；管理员 / 角色 / 权限 CRUD；CP、SP 及绑定；影片库编目与海报上传；操作日志与运行日志查询；HTTP JSON API（Protobuf 生成）。

刻意延后

终端播放器、CDN 调度引擎、转码流水线、计费结算、gRPC 对外暴露（入口已预留，当前 cmd/crow 只挂 HTTP）。Todo 示例仅作模板残留。

05 · 分层

DTO · DO · PO 单向流动

Crow 沿用 Kratos 模板契约：边界转换，领域不碰传输，持久化不碰 proto。

Client→ DTO proto→ service→ DO biz→ data→ PO / SQL
service 解析请求、FieldMask、列表过滤，调用 usecase。嵌入 Unimplemented Server。 只说 DTO ↔ DO
biz 领域对象、用例、Repo 接口、错误原因。权限目录等业务规则住在这里。 不 import data / service
data 实现 Repo，*Data 持有 *sql.DB。构造函数返回接口而非具体类型。 不 import DTO
server 组装 HTTP、注册服务、海报上传与静态 /uploads/。 无业务规则
cmd Wire 注入唯一交汇点。 wire_gen.go 不手改

06 · 领域

三块核心模型

VOD

节目树

Category 可有父级。Video 挂分类，带编码、类型、海报、年份时长。Episode 属于影片。Media 挂影片或剧集，记录 URL、码率、分辨率、体积。

类型：1 电影 · 2 剧集 · 3 综艺 · 4 其他

CDN 合作

CP ↔ SP

Cp：注入侧身份，cp_code 全局唯一。Sp：分发侧身份，可选 JSON 配置。CpSp：多对多绑定与状态（正常 / 禁用 / 冻结）。

IAM

RBAC

Admin 多角色；Role 经 GroupPermission 挂权限。Permission 树：模块 handle 与 HTTP 路径 / 方法对齐，程序内预置目录。

07 · 安全

登录之后才是后台

POST /v1/login 账号密码换 access / refresh。前端存 crow.auth，后续请求带 Authorization: Bearer。
JWT HMAC，claim 含 sub（管理员 ID）、account、use=access。过期由配置 auth.jwt.expires_in（默认 7200s）。
中间件 除登录外，/v1/admins|roles|permissions|cps|sps|videos|… 均校验 Bearer。失败 401。主体写入 context。
审计 管理写操作记 AdminOperationLog。进程日志可经系统日志查询。

密钥在 configs/config.yaml，演示环境勿把真实密钥提交仓库。

08 · 契约

Protobuf 即 API

资源风格：create / get / list / update / delete。List 带 page_size、page_token、filter、order_by；更新带 FieldMask。源文件在 api/*/v1/*.proto，用 protoc 生成 Go 与 OpenAPI，禁止手改 *.pb.go。

服务前缀职责
LoginService/v1/login签发令牌
AdminService/v1/admins 等账号、角色、权限、两类日志
Cp / Sp / CpSp/v1/cps|sps|cp-sps合作方与绑定
VodService/v1/videos 等分类、影片、剧集、媒资
UploadPOST /v1/videos/posters/upload海报，≤10MB，落到 uploads/posters

播控管理中心信息架构

登录后默认进入影片库。侧栏分三组；关联表（管理员-角色、CP-SP）可在表单里勾选，列表入口隐藏以免干扰运营。

内容管理

影片库（自定义页：分类筛选、新建、详情编目）
内容提供商
内容服务商

系统管理

管理员 · 角色 · 权限
操作日志 · 系统日志（只读）

交互模式

通用资源：列表 → /new → /:id/edit。影片：海报上传、剧集与 Media 嵌在详情页。

10 · 关键路径

两条必须讲清的链路

上架一部剧

1. 分类就绪
2. 创建 Video（类型=剧集，编码唯一）
3. 上传竖/横海报
4. 按集号建 Episode
5. 为每集登记 Media（地址、码率、分辨率）

开通一条注入路由

1. 建 SP（编码 = 协议 SPID）
2. 建 CP（编码 = 协议 CPID）
3. 在 CP 表单勾选 SP，写入 CpSp
4. 状态保持「正常」，禁用/冻结切断路由

12 · 约束

质量与演进边界

必须遵守

后端 Go，前端 React。分层方向不可逆。新增资源走 checklist：proto → 生成 → biz → data → wire → server。测试按层假依赖，不跨层打穿。

已知缺口

权限目录已建模，控制台路由尚未按 handle 细粒度裁剪。海报为本地盘，生产需对象存储。刷新令牌接口尚未作为一等公民暴露。
